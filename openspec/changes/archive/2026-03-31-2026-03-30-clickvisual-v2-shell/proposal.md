# 提案：ClickVisual v2 独立前端壳层

## 背景与原因

ClickVisual 当前正式前端仍是 `ui/` 中的 Umi 4 + Ant Design Pro 应用，而新设计已经在 `v2/` 中形成了完整的五模块原型和新的视觉语言。继续在旧前端中渐进叠加，会把新的信息架构、设计系统和 AI 入口绑死在旧页面模型与旧接口形态上，后续返工成本高。

同时，本次目标不是只做某个页面的局部重构，而是让以下五个模块在首期同时具备可运行壳子：

1. 大盘总览
2. 日志查询
3. 定时报表
4. 告警系统
5. 配置中心

这要求我们以新的前端应用和新的页面契约为中心组织工作，而不是继续依赖旧 UI 和旧 API 拼装。

同时，用户已经确认 `v1` 与 `v2` 需要长期共存，并且能够随时切换，而不是做单向替换式升级。这意味着首期设计必须把双版本入口、路由隔离、灰度切换和回退路径视为正式需求，而不是后续补丁。

## 变更内容

- 在仓库内新增一个独立的 `v2` 前端应用，作为 ClickVisual v2 的承载体
- 保留现有 `v1` 前端应用，并提供 `v1` 与 `v2` 的可切换入口
- 定义一组面向页面能力的 `v2` 专用接口/聚合接口
- 用统一平台壳层承接全局导航、筛选、时间范围、通知和 AI 动作
- 将五个模块按垂直业务域组织，并在首期都达到“可运行壳子”标准
- 以 `v2/stitch/` 下的设计稿作为当前视觉真源，对五个模块进行统一视觉重做
- 将当前 change 作为后续执行任务的唯一规格与任务真源

## 新增约束：视觉真源

当前 `ui-v2` 已具备基础路由、报表主链路与剩余模块的最小壳层，但视觉质量与 `v2/stitch/` 中的设计稿存在明显偏差，不能继续通过局部美容来修正。

本轮执行改为：

- 以 `v2/stitch/chronos_amber/DESIGN.md` 为设计系统约束
- 以 `v2/stitch/*/code.html` 为五个模块的页面结构和视觉参考
- 先统一共享视觉底座，再分别重做五个模块页面
- 已具备真实行为的 `report` 主链路在视觉重做过程中保留功能闭环，不允许因视觉改造退回到纯静态页

## 非目标

- 当前 change 不要求首期完成所有深层后端实现
- 当前 change 不要求替换现有 `ui/` 主应用
- 当前 change 不要求首期实现完整 AI 效果，只要求定义结构化入口和降级路径
- 当前 change 不要求首期完成全部性能优化和查询优化

## 成功标准

- OpenSpec 中存在清晰的 `design.md` 和 `tasks.md`，后续执行以其为真源
- 新前端应用与旧前端应用边界明确，不混用页面实现
- `v1` 与 `v2` 能在同一系统中共存，并支持用户显式切换与安全回退
- 五模块都有正式路由和最小主流程
- 前端只依赖 `v2` 契约层，不直接耦合零散旧接口
